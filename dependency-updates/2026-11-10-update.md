## Follow-up: propTypes → TypeScript (approved code change)
- **Why:** React 19 silently ignores `propTypes` on function components (https://react.dev/blog/2024/04/25/react-19-upgrade-guide). You chose TypeScript as the replacement.
- **What changed:**
  - `ContainerProvider`, `Layer`, `LayerControl`, `AttributeTable` and `FeatureInfoContainer` were renamed `.jsx` → `.tsx` (with `git mv`) and given typed props interfaces. Their propTypes blocks and imports were removed.
  - New `src/Components/Layers/types.ts` holds `Overlay` and `LayerUpdate`. `LayerUpdate.opacity` is `number | string` because the range input delivers a string that `LayerPresenter.updateLayer` parses. The existing behavior is kept and documented, not changed.
  - `map` props are typed `Map | null`, because `OlMap` starts with `useState(null)`.
  - `FeatureInfoContainer`: the subscription callback moved inside the existing `if (map)` block so TypeScript can see `map` is non-null. It runs in exactly the same cases as before.
  - `src/main.jsx` imports `./Shared/IOC/ContainerProvider` without the `.jsx` extension.
  - `tsconfig.json` sets `strict`, `allowJs` and `checkJs: false`, so only `.ts`/`.tsx` files are checked; it includes `vite/client` types. A `typecheck` script (`tsc -p .`) was added, and `build` now runs it before `vite build`.
  - Lint: `typescript-eslint` recommended rules apply to `*.ts`/`*.tsx`. No new findings.
  - Dependencies: removed `prop-types`; added `typescript@~6.0.3` and `typescript-eslint@^8.72.2`. TypeScript uses a `~` range because `typescript-eslint` declares the peer `typescript >=4.8.4 <6.1.0`, so the latest TypeScript (7.0.2) would break that peer.
- **Limitation:** `OlMap.jsx` and `main.jsx` are still JS and unchecked, so the props they pass to `FeatureInfoContainer`/`LayerControl`/`ContainerProvider` are not type-checked. The `LayerControl`→`Layer` and `FeatureInfoContainer`→`AttributeTable` usages are checked.
- **Audit side effect:** `typescript-eslint@8.72.2` depends on `minimatch@^10.2.2` (10.2.6 installed), which matches GHSA-g3hv-75wg-m249 (moderate, ReDoS, affects `>=7.0.0 <11.0.1`), https://github.com/advisories/GHSA-g3hv-75wg-m249. No patched version is within the declared range. npm's suggested fix is a downgrade to `typescript-eslint@8.36.0`, which was not taken. This is dev-only: the vulnerable input is glob patterns from your own config. It was accepted and not overridden.
